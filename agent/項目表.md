# 專案結構與依賴

| 路徑 | 用途 | 主要依賴／關係 |
|---|---|---|
| `cmd/grok2api/` | Go 主服務入口 | 組裝 `internal/` 各模組 |
| `cmd/grok2api-migrate/` | 資料庫遷移工具入口 | 使用 `internal/migrate/` 與 `migrations/` |
| `internal/proxy/` | 聊天請求、串流與上游切換 | 使用 protocol、pool、upstream、store |
| `internal/protocol/` | OpenAI、Anthropic、Responses 與工具呼叫正規化 | 供 proxy 與 server 使用 |
| `internal/server/` | HTTP API 與管理台路由 | 使用 proxy、admin、store |
| `internal/store/` | PostgreSQL、Redis 與持久化抽象 | 供 server、pool、registration 使用 |
| `internal/upstream/` | Grok 與 OIDC 上游客戶端 | 供 proxy、registration 使用 |
| `internal/registration/` | Go 註冊協調與 sidecar client | 呼叫 Python registration sidecar |
| `grok2api/` | Python sidecar 與相容層 | 由 Go 主服務透過 loopback 使用 |
| `grok-build-auth/` | Grok Build OAuth 引擎 | 供 Python 註冊流程使用 |
| `grok-build-auth/xconsole_client/oauth_protocol.py` | 純 HTTP Grok Build OAuth、PKCE、cookie-setter 與 consent | 由 `grok2api/upstream/grok_build_adapter.py` 呼叫；測試位於 `tests/test_oauth_protocol.py` |
| `scripts/` | 註冊 sidecar、建置與維運腳本 | 由 entrypoint、開發或管理流程呼叫 |
| `static/` | 管理台前端來源與建置產物 | 由 Go server 提供 |
| `contracts/` | 相容性 manifest 與 schema | 由 GitHub Actions 驗證 |
| `.github/workflows/` | CI、映像建置與發佈 | 驗證 Go、Python、contracts 與版本 pin |
| `agent/` | 任務歷史、專案結構與操作紀錄 | 開發助理維護 |

## 主要執行鏈

1. 用戶端請求進入 `internal/server/`。
2. `internal/proxy/` 依協定正規化請求並從 pool 選擇帳號。
3. `internal/upstream/` 呼叫 Grok；狀態由 PostgreSQL 與 Redis 保存。
4. 註冊需求由 Go registration client 呼叫 Python sidecar，再匯入共用帳號格式。
